# 实现原理

[返回 README](../README.md)

本文对应当前代码，不描述尚未实现的 SDK 或后台服务。

## 存储对象

| 对象 / 表 | 保存的内容 | 用途 |
| --- | --- | --- |
| `records` | 问题、完整回答、最近最多 6 条对话上下文、空间与记录时间 | 原始证据与归档 |
| `memories` | 独立事实或问答摘要、向量、空间、冷热状态、来源 ID、父记忆 ID、原因与时间 | 匹配和整理 |
| `stages` | 阶段摘要、覆盖的完整来源 ID、生成时间与空间 | 压缩历史证据 |
| `memory_stages` | 记忆与阶段摘要的对应关系 | 检索时读取当前阶段 |
| `memory_kinds` | 记忆 ID 与 `qa/fact` 类型 | 独立保存类型，不混入摘要向量 |
| `memory_operations` | 合并、覆盖、删除的目标、输入、结果、原文、原因与时间 | 操作审计 |

所有原文与记忆保存到 SQLite。向量以 JSON 保存；服务端读取同一空间的热区记忆后，用 TypeScript 计算余弦相似度。SQLite 的普通索引用于空间和状态筛选，没有原生向量索引。

`sourceIds` 保存扁平化的完整原文来源；`sourceOrder`（仅合并生成的记忆）保存本次合并时 LLM 按新摘要相关性排列的原文优先顺序；`parentIds` 保留直接父记忆关系。取原文不需要递归遍历冷区或父节点。阶段压缩后，日常流程只取未覆盖原文及阶段摘要，完整来源仍留在本地。

## 回答与写入顺序

1. 将问题生成向量，检索热区。
2. 组合近期对话与检索证据，生成回答。页面通过 SSE 接收增量文本。
3. 回答完整结束后，保存问题、完整回答和近期上下文。流式回答在完成前中断时不调用记忆写入。
4. 调用一次 LLM，提取本轮新增或明确更新的独立事实，最多 20 条、每条最多 700 个字符；同时生成 `qaSummary`。有事实时使用独立事实，没有事实时使用一条问答摘要。
5. 本轮摘要批量生成各自的向量，并从本轮写入前的热区快照中取最多 3 条相似候选，真实模式默认阈值为 0.6。问答摘要只召回问答类整理候选。
6. 所有有候选的摘要统一交给一次批量 LLM 判断。无候选时直接新增，不调用合并模型。
7. 校验并分配操作目标，每个旧候选本轮最多分配一次；通过校验的合并 / 覆盖摘要统一批量生成向量，然后按输入顺序执行操作。即使某条合并向量失败，也不把已分配的旧候选转交本轮其他事实，后续冲突事实仍保存独立摘要。完成后向页面返回整理结果。

向量接口多输入时发送 `input: string[]`，单输入仍发送字符串。返回数量必须一致；提供 `index` 时按索引还原输入顺序并拒绝缺失、重复或越界索引，不提供索引时按返回顺序对应。每批向量须非零且维度一致。批量请求失败或响应无效时，仅对该批回退为逐条请求，最多 3 个并发；逐条失败不再自动重试，成功项继续处理，失败项原文保留并提示 partial。正常路径不会增加聊天 LLM 调用，向量失败回退可能增加请求数和等待时间。

Markdown 只影响展示：聊天中的 AI 回复、记忆库原始回答和阶段归档使用同一个渲染组件，流式增量到达时更新格式。用户输入、存储的原始文本、Embedding 和模型请求不会因页面渲染被改写。

一条事实围绕同一主体的一个可独立更新的属性。多个事实可以共享本轮原始问答；摘要向量不代表已经对完整原文建立了另一套向量索引。

提示词要求事实来自当前用户问题；助手回答和近期上下文仅用于理解指代，不把助手猜测或复述当作本轮用户事实。没有用户事实时，使用同一次调用产生的问答摘要，最多 700 字符。摘要不添加固定类型前缀或验证提示，Embedding 只接收摘要正文。兼容旧模型输出：缺少或留空 `qaSummary` 时用当前问题和回答的节选建立摘要，不额外调用模型；整个提取输出无效时仍返回 partial。

类型通过 `memory_kinds` 独立持久化，批量整理资料携带 `kind=qa/fact`；代码拒绝两类之间的合并或覆盖。未迁移的旧记忆暂时兼容原固定前缀识别，其余缺少类型的记忆默认为事实。事实输入仍可召回问答候选，以便用户明确撤回问答记录；删除继续要求本轮用户原文依据。检索回答时两类热区记忆都可参与，原始回答始终作为未经验证的助手内容。旧版未索引问答不会自动回填。

### 批量操作

| `action` | 对应关系 | 实际行为 |
| --- | --- | --- |
| `add` | 新事实、无关或无法确定的冲突 | 保存原 incoming 摘要为热区记忆 |
| `merge` | `duplicate` / `complement` | 两条输入摘要进入冷区，生成新的热区摘要 |
| `replace` | `update` | 以明确更新的值生成新热区摘要，旧值与输入摘要保留在冷区 |
| `delete` | `retract` | 目标进入冷区，撤回输入也保存在冷区，不生成新热区事实 |

覆盖与合并使用同一套事务与来源继承机制。较晚的明确长期偏好可以更新旧偏好；临时要求不应覆盖长期要求。不同主体、不同属性或适用条件不同的事实不应只因主题相似而合并。

删除必须给出本轮用户问题中逐字出现的 `deletionQuote`。代码校验候选归属、引用和热区状态，LLM 判断撤回语义。「删除」不是物理擦除，不清理其他记忆、归档或近期对话中的相同信息。

回答提示词要求：如果看到用户明确撤回某项信息，且之后没有明确恢复授权，就不要在回答或解释撤回原因时复述旧值；“还记得吗”本身不视为恢复授权。用户明确恢复使用旧信息或重新提供新值时，按其授权范围处理。普通配置更新仍允许回答历史变化。

提取提示词进一步限定只处理当前问题的新增内容：历史撤回不能在后续无关问答中重新提取；当前撤回摘要只保留目标属性和意图，不抄写旧值。整理和阶段摘要也要求避免通过“记录撤回历史”重新保存被撤回值。这些均为提示词约束，没有新增撤回标签或硬过滤机制；原文仍保留并可能发送给模型。若撤回依据没有进入上下文、模型不遵守规则或摘要回退使用了原文节选，仍可能重新出现旧值，不能承诺彻底遗忘。

同一轮新事实之间不互相合并，同一旧候选最多成功处理一次。产生的新记忆立即保存，不递归重新处理；以后收到相关输入时才有机会再次整理。候选争用或并发请求已修改目标时，保留独立摘要并提示 partial。

旧版模型输出没有 `action` 时，代码仍兼容按 `relation` 推导合并或覆盖行为。

整理提示词只保留一份完整的 `decisions` JSON 格式，要求输出 action、deletionQuote、stageSummary 和 `sourceOrder` 等字段。合并时，LLM 按新摘要与本次可见原文的相关性排序来源 ID；代码只接受该 incoming 与选中 candidate 的来源 ID，过滤无效或重复 ID，再将遗漏的可见来源和压缩归档来源追加，确保来源完整。检索优先读取该顺序中的原文；旧模型未返回排序或旧记忆没有排序时，继续按时间取最近原文。代码先检查 JSON 与外层 decisions 数组（最多20项），再逐项校验字段及 incomingId / candidateId 归属。某项字段错误不影响同批其他有效项；同一 incomingId 重复出现时，其所有项均不执行，未知 ID 不操作，缺失项保存独立摘要。整份 JSON 或外层结构损坏时仍整批回退，不尝试修补不完整 JSON，也不追加模型重试。

提示词要求 reason 为最多80个字符的单句理由（含空格、标点，英文按字母计数），避免逐个展开候选分析。80字符是生成要求，代码仍保留原有500字符上限以兼容历史输出；没有截断模型文本来绕过校验。字符要求不保证模型始终遵守。

写入结果附带 `diagnostics`，区分 json、schema、decision、mapping 阶段，记录字段路径、校验代码、已知 incomingId 和接口提供的 finishReason（如 length）。同样的元数据写入服务日志，不记录原始模型输出或历史文本；诊断信息不代替操作关系、撤回引文、阶段摘要、目标争用和事务状态校验。

### 模型调用数量

正常 live 问答包含一次回答调用、一次摘要提取调用，以及有候选时最多一次批量整理调用。阶段压缩在同一次批量整理中完成，不另加调用；无候选时跳过批量整理。

Embedding 另计：问题一次，新增摘要与通过校验的合并摘要各批量请求一次；批量失败时最多3个并发逐条回退，详见写入流程。模型 HTTP 请求的单次超时为 45 秒，无自动重试。

回答是流式传输的；事实提取和批量整理仍返回完整 JSON，并由 Zod 校验。页面在回答结束后显示整理状态，收到完成事件后才允许发送下一轮。

## 检索

### 首轮

仅比较相同 `scope`、相同向量空间的热区摘要。真实模式默认相似度最低分 **0.45**，取最多 20 条候选，再在证据预算内选最多 3 条。

没有达到阈值的候选时，额外返回最接近的 3 条热区记忆供页面查看。这些建议不加入回答证据。阈值候选存在但因预算没能选入时，不会触发这个低分建议分支。

### 第二轮

页面固定使用 `expand`。只有首轮恰好选入 1 条记忆且仍有证据预算时，才以该记忆作为起点尝试关联扩展。首轮 0 条、2 条或 3 条都不会扩展；没有剩余预算时也不会扩展。

每个首轮起点最多找 5 个邻居。邻居既要与原问题达到检索阈值，也要与起点达到阈值，再按下式排序：

```text
最终分数 = 与原问题的相似度 × 75% + 与首轮记忆的相似度 × 25%
```

首轮最多选 3 条；只有首轮恰好命中 1 条时才按该记忆扩展，第二轮最多再选 2 条。每条命中记忆最多读取最近 2 条未被阶段摘要覆盖的原文；两轮共用最多 6 条原文 / 阶段证据预算。邻居由多个起点找到时保留最高分；只引用已选证据、无法补充新来源的记忆不会重复选入。

第二轮同样只查热区，不是读取冷区历史。摘要到原文的追溯通过 `sourceIds` 完成，和关联扩展是不同操作。API 另保留 `sources` 策略：使用同样首轮筛选和证据追溯，跳过邻居扩展。

## 回答证据与预算

每条命中记忆最多读取 4 条未覆盖原文候选，默认只选 2 条：有合并排序时按相关性优先，否则按记录时间倒序选择。同一时间按原文 ID 升序确定顺序；选定原文已被引用时不为凑数追加更旧来源。不同记忆共享预算并按原文 / 阶段 ID 去重。完整原文关联仍保留，候选数上限不裁剪存储的 `sourceIds`，也不限制合并判断所需的未覆盖资料。

默认最多 6 条证据（原文与阶段摘要合计）、每条正文最多 5,000 字符，实际发送的历史证据 JSON 同时受 18,000 字符与 6,000 估算 token 限制。每个阶段摘要算一条证据。长记录可以节选并标记 `truncated`；数据库原文不截断。预算不足时可能连阶段摘要也无法选入。

`context` 是发给回答模型的实际历史证据；`records` 是相应的完整原文，`stages` 是选中的阶段摘要。完整 `records` 供页面追溯，不会绕过预算再整份发送。

上下文去重针对完全相同的消息：

- 批量整理使用共享 `contexts` 字典，各原文通过 `contextIds` 保留消息顺序和出现次数。
- 回答证据用 `contextRef` 引用之前完整证据中的同一消息。被截断的证据不作为引用目标。
- 旧的非 JSON 上下文保留原样；不调用 LLM 做语义去重，也不改写数据库。

该去重不覆盖所有信息重叠，尤其不等于消除了近期聊天与历史证据之间的全部重复。token 估算采用 ASCII 约 4 字符/token、非 ASCII 约 1.5 tokens/码点；不是模型 tokenizer，也不计算系统提示、当前问题、近期对话和输出的完整开销。

## 阶段压缩

只在本次决定合并或覆盖时检查压缩条件：未覆盖原文 **达到 5 条**，或这些完整记录序列化总长度 **超过 12,000 字符**。四条不触发条数条件，恰好五条即触发；字符条件仍可提前触发。普通新增不会独立触发压缩，已被阶段摘要覆盖的来源不重复计入本轮未覆盖条数。

第一次压缩以当前可用原文为依据；后续判断和再次压缩只使用「上一版阶段摘要＋未覆盖新增原文」。模型在同一次批量整理结果中额外输出最多 4,000 字符的 `stageSummary`；检索用的单事实 `summary` 仍独立生成向量。

新阶段覆盖来源由代码确定。旧原文、旧阶段与冷区历史继续保留，查看详情时才按需展开归档。模型不能恢复旧阶段已经遗漏的细节。阶段摘要包含当前值和必要条件，并尽量保留关键变化、否定、时间和不确定性。

批量整理输入按原文 ID 去重，只发送未覆盖来源 ID、来源数量和阶段内容，不携带完整历史来源列表。资料 JSON 默认受 64,000 字符和 20,000 估算 token 限制；预算不包含系统提示和输出。超限、模型格式无效或缺少必需阶段摘要时，保留独立事实并返回 partial，不增加调用次数。

## 时间、空间与失败处理

原文、记忆、阶段摘要都有 `createdAt`，代表记录或生成时间。当前没有独立结构化的生效时间字段；用户明确声明的生效日期以文本保留在摘要 / 原文中，提示词要求不要把记录时间当作生效时间。

真实向量空间标识包含 Embedding 服务地址与模型名，demo 使用自己的标识。更换 Embedding 模型不会重建旧向量，旧原文仍可查看。同地址同名称背后的模型变化也不会自动迁移；不同维度无法有效比较。

回答生成失败时，`remember` 尚未执行，不能承诺本轮原文已保存。完整回答之后的事实提取失败会保留原文；向量或整理失败时可能留下未索引原文或独立事实。页面显示错误或 partial；当前没有自动重试和重建队列。

若客户端在已开始的记忆整理期间断开，服务端整理可能继续完成，页面无法据此确认最终状态。重新查看记忆库核对即可，不会自动重发整轮对话。

`scope` 只是数据库过滤条件，客户端可自行传入。当前没有身份认证，不能将空间名称视为用户权限。
