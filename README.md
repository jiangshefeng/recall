# Recall

用 TypeScript 实现的本地动态对话记忆应用。

Recall 从对话中提取独立事实，检索相关记忆辅助回答，再由 LLM 判断新信息应该新增、合并、覆盖，还是将旧记忆移入冷区。摘要用于向量匹配，原始问答和阶段摘要用于回答与追溯。

目前是 **Next.js 应用和可阅读、可修改的实现原型**，还没有独立 npm SDK、文件知识库导入或多人服务的权限体系。

## 已实现

- **独立事实记忆**：一次提取最多 20 条事实，分别生成向量，共享本轮原始问答。
- **问答摘要兜底**：没有用户事实时，同一次提取生成一条问答摘要进入热区；类型单独保存，向量只使用摘要正文。
- **批量整理**：有候选时，一次 LLM 调用判断新增、合并、覆盖、删除，不逐条调用或递归合并。统一 JSON 输出协议，逐项校验；单项格式错误只让对应事实回退为独立摘要，其他有效决策继续处理，并返回不含原文的错误路径与代码。
- **批量向量**：新增摘要、通过校验的合并摘要分两批生成向量；批量失败时回退为最多 3 个并发的逐条请求，保留成功结果。
- **LoCoMo 评测脚本**：支持完整长对话导入、五类问题抽样、原文 RAG 对照、断点续跑、复用数据库补测、新增调用费用估算预算及官方 QA 评分；单段对话结果不代表全量成绩，见 [评测说明](docs/locomo.md)。
- **冷热区**：热区参与检索；冷区保留合并前、被覆盖或被撤回的历史。
- **条件式两轮检索**：默认先取最多3条相关记忆，结果不足且预算允许时再扩展最多3条关联记忆。
- **阶段压缩**：合并时未覆盖原文达到5条即进行阶段整理；后续使用已有阶段摘要与新增原文增量整理，完整原文仍可查阅。
- **来源与预算**：每条记忆最多读取最新4条原文候选，默认只发送最近2条，完整关联保留；原文、重复上下文去重传输，并限制历史证据条数、字符数和估算 token。
- **流式回答**：真实模型通过 SSE 逐段输出；用户消息在右，AI 回复在左。
- **Markdown 展示**：AI 回复、原始回答与阶段归档支持标题、强调、列表、引用、链接、表格和代码块；流式输出时同步渲染，宽表格和代码块可横向滚动。
- **本地界面**：黑白聊天界面，右侧记忆路径可折叠，另有记忆库与模型配置说明。

## 快速启动

需要 Node.js **22.13+**、npm 和 Git。SQLite 使用 Node 内置 `node:sqlite`，无需额外安装数据库服务；Node 22 可能提示实验性警告。

```sh
git clone https://github.com/jiangshefeng/recall.git
cd recall
npm ci
npm run dev
```

打开 [http://localhost:3000](http://localhost:3000)。Windows PowerShell 如果限制 `npm.ps1`，将命令中的 `npm` 换成 `npm.cmd`。

新下载的项目默认运行 **demo 模式**，无需 API Key。点击「载入示例」后，可体验完整检索和追溯流程。

demo 使用字符 bigram 哈希向量、规则回答、完全重复摘要去重和一次预设合并；不调用真实 LLM，也不模拟语义覆盖、删除或阶段压缩。真实模型流式输出的效果需要在 live 模式体验。

## 使用真实模型

在新项目中复制配置模板：

```sh
cp .env.example .env.local
```

PowerShell 对应命令为 `Copy-Item .env.example .env.local`。已有配置时直接编辑，不要覆盖自己的密钥。

例如，聊天使用百炼千问，Embedding 使用本机 Ollama：

```dotenv
RAG_MODE=live

LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_API_KEY=填写你的百炼密钥
LLM_MODEL=qwen3.8-max

EMBEDDING_BASE_URL=http://127.0.0.1:11434/v1
EMBEDDING_API_KEY=ollama
EMBEDDING_MODEL=qwen3-embedding:0.6b

RAG_SEARCH_THRESHOLD=0.45
RAG_MERGE_THRESHOLD=0.6
```

安装并启动 [Ollama](https://ollama.com/download)，下载向量模型：

```sh
ollama pull qwen3-embedding:0.6b
```

若 Ollama 服务尚未运行，执行 `ollama serve`；已运行时不需要重复启动。配置完成后重启 Next.js。

聊天与向量服务可以来自不同供应商。聊天接口须兼容 `chat/completions`，页面流式回答还需要支持 `stream: true` 和 SSE；向量接口须兼容 `embeddings`。BASE_URL 写到 API 前缀，不包含完整 endpoint。

上述百炼地址对应中国内地北京地域；密钥和服务地域需要一致。`ollama` 是本地接口的占位密钥。其他供应商需使用相应服务的密钥和模型名称。

完整参数见 [配置说明](docs/configuration.md)。仓库中的 `start-local.cmd` / `start-local.ps1` 是原 Windows 开发环境的辅助脚本，含固定 `D:\Ollama` 路径；新用户按上述通用步骤启动即可。

## 在页面中使用

1. 在「记忆对话」输入问题或希望记住的信息。用户消息右对齐，AI 回复左对齐。
2. live 模式收到模型增量文本后立即显示。回答结束后显示「正在整理记忆」，完成后附上整理结果；本轮整理完成前不能继续发送。

3. 点击右上角「展开记忆」查看本轮候选、关联、实际发送的证据和预算。再次点击、使用面板关闭按钮或按 Esc 可收起。点击某条回答下的「查看本次检索」可打开对应证据。
4. 在「记忆库」查看热区摘要、冷区历史与完整原始问答，按来源追溯；阶段摘要的归档原文按需展开，展开内容不会自动追加给模型。
5. 在「模型与配置」切换 `scope` 或查看模型状态。模型密钥仍在服务端环境变量中配置，页面不提供密钥编辑器。

AI 回复按 Markdown 渲染，用户输入保持原文。展示使用 `react-markdown` 与 `remark-gfm`，支持删除线和任务列表；代码块保留缩进，当前不提供语法高亮或数学公式渲染。原始 HTML 不作为页面元素执行。数据库与后续模型调用仍使用原始 Markdown 文本。

「新对话」清空当前浏览器对话视图，**不会清空数据库记忆**。当前聊天消息列表不持久化到浏览器，刷新后视图会重置；已入库的问答和记忆继续保留。

## 一轮对话如何工作

```text
问题 → Embedding → 检索热区记忆 → 原文 / 阶段摘要 → 流式回答
                                                       ↓
                                                完整问答先保存
                                                       ↓
                            一次 LLM 提取 → 多条事实 / 一条问答摘要 → 向量
                                                       ↓
                            匹配旧热区候选 → 一次批量 LLM 判断 → 保存
```

当前真实模式检索阈值是 **0.45**，合并候选阈值是 **0.6**。两个阈值作用不同：前者决定哪些历史可以参与回答，后者决定哪些旧记忆交给 LLM 整理；达到分数不会自动合并。

记忆整理只处理本轮输入，不执行后台定时合并。完整流程、阶段压缩和失败处理见 [实现原理](docs/architecture.md)。

普通 RAG 对照的小规模 LoCoMo 测试采用原文分块、单轮向量 Top-K 检索，与动态记忆共享回答模型和最终证据预算；追加批次支持动态、普通 Top3、普通 Top6 三组固定对照，跨报告共用新增调用预算。新的 DeepSeek 对照脚本从头建库，验证 3+3、每条默认最近2条原文、5条阶段压缩的配置，共用100万聊天token上限；重复回答单列。测试范围、token 上限及结果限制见 [LoCoMo 说明](docs/locomo.md)。

### 为什么问了问题，热区数量没有增加？

每次完整回答后都会尝试生成摘要：有用户事实就拆成独立事实；没有用户事实（包括纯提问、寒暄）时，生成一条问答摘要。摘要记录问题与答复，不添加固定类型前缀或验证提示，Embedding 只接收摘要正文。问答类型另存为元数据，模型仍区分用户陈述与助手建议。这仍是一次提取调用。

没有达到 0.6 的整理候选就直接新增；有候选才交给 LLM 批量判断。问答摘要只与问答摘要合并或覆盖。并入旧记忆、覆盖或撤回时，热区总数可能不增加。提取或向量请求失败仍可能只保存原文，页面会提示 partial。旧版本已保存但没有摘要的问答不会自动补建索引。

## 开发与测试

```sh
npm test
npm run build
npm run test:e2e
```

`npm test` 使用本地数据和模拟模型，不需要密钥。浏览器测试默认使用本机 Microsoft Edge，并在 3100 端口启动独立 demo 服务；测试数据库与用户默认数据库分开。

要观察记忆是否改善回答，配置真实模型后运行 `npm run test:compare`：使用独立数据库，对比“最近 6 条聊天”和“最近 6 条聊天＋动态记忆”，15 题各测两次。逐题预期、实际回答、检索证据与耗时保存在 `artifacts/memory-comparison-*/`，评分方法见 [开发与维护](docs/development.md)。

本地生产方式运行：

```sh
npm run build
npm start
```

两个启动脚本均默认只监听 `127.0.0.1`。更多检查、真实模型验证、备份方法和脚本影响范围见 [开发与维护](docs/development.md)。

## 当前边界

- SQLite 保存向量 JSON，TypeScript 线性计算余弦相似度，尚未使用数据库向量索引，适合本地小规模使用。
- `scope` 是数据分区，不是登录认证；当前接口没有用户权限和配额管理。
- LLM 只判断召回的候选，没匹配到旧记忆时不会全库寻找合并或删除目标。
- 「删除」定义为目标移入冷区、不再参与检索；原文保留，不是物理擦除，也不会清理其他记忆或近期对话中的相同内容。
- 提示词要求在看到用户撤回后不复述旧值，并避免从历史上下文重新提取已撤回内容；依赖模型理解，不是标签过滤或彻底遗忘保证。
- 阶段摘要是有损整理。原文保留供查阅，日常回答与后续合并不会自动重新加载已覆盖的归档。
- token 预算使用文本估算，且分别针对历史证据和合并资料，不是整个请求的精确上下文上限。
- 还没有重试队列、自动重建向量、独立 SDK、流式回答停止按钮或完整的聊天会话恢复功能。

模型拆分、覆盖和撤回的语义判断仍可能出错。代码校验结构、来源和状态，不能保证模型始终理解正确。对外部署前需要补充身份认证和权限校验；本地 SQLite 也需要可持久保存的磁盘。
