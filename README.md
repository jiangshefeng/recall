# Recall · 动态记忆 RAG

Next.js + TypeScript 的本地原型：问答完整存储、上下文摘要、LLM 关系判断与合并、冷热区、来源追溯、两轮检索。

页面统一使用条件式两轮关联检索，命中后自动追溯原文，不再提供单独的模式切换。首轮结果充足时跳过二轮。内部 `sources` 模式保留用于兼容接口和检索对比测试。

## 本机配置：千问 + Ollama

本机 `.env.local` 已设置为真实模式，聊天模型使用国内百炼 `qwen-plus`，向量模型使用本机 Ollama 的 `qwen3-embedding:0.6b`。

只需在 `.env.local` 中填写 `LLM_API_KEY=你的百炼密钥`，保存并重启 Next.js。这里使用中国内地（北京）的兼容接口 `https://dashscope.aliyuncs.com/compatible-mode/v1`；若密钥来自其他地域，需要同时调整服务地址。网页千问会员、Coding Plan 专用密钥不能直接当作这个通用百炼接口的配置。

向量模型配置如下，`ollama` 是占位值，不需要购买向量 API 密钥：

```dotenv
EMBEDDING_BASE_URL=http://127.0.0.1:11434/v1
EMBEDDING_API_KEY=ollama
EMBEDDING_MODEL=qwen3-embedding:0.6b
```

本机采用 Ollama 官方 Windows 免安装版，位于 `D:\Ollama`，保留 CPU/Vulkan 组件，不含大型 CUDA 库及桌面托盘程序；可执行文件签名已验证。模型保存在 `D:\Ollama\models`。新终端可执行 `ollama list` 检查模型。

重启电脑后，双击项目中的 `start-local.cmd`，它会在后台启动本地 Ollama 和 Next.js（如果已经运行则不重复启动）。也可单独执行 `D:\Ollama\ollama.exe serve`。模型首次加载会比后续请求慢。LLM 摘要、合并和回答仍会调用云端千问。

## 启动

需要 Node.js 22.13+（使用内置 `node:sqlite`，Node 22 可能显示 ExperimentalWarning）。在 PowerShell 中运行：

```powershell
cd D:\RAG
npm.cmd install
npm.cmd run dev
```

打开 http://localhost:3000。默认仅监听本机。无模型配置时为明确标注的 **demo 演示模式**：字符 bigram 哈希相似度、规则回答、完全重复摘要去重；不是语义模型，也不能据此评估真实 RAG 效果。点击「载入示例」生成 5 条问答和一次**预设**合并，体验追溯和二跳检索。重复点击不会重复载入。

## 真实模型

```powershell
Copy-Item .env.example .env.local
```

编辑 `.env.local`，把 `RAG_MODE` 改为 `live`，填写 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`，以及 `EMBEDDING_BASE_URL`、`EMBEDDING_API_KEY`、`EMBEDDING_MODEL`。重新启动服务。

聊天使用兼容 OpenAI 的 `/chat/completions`，向量化使用 `/embeddings`。两个模型可来自不同供应商。BASE_URL 填到 `/v1` 等 API 前缀，不要包含完整 endpoint。真实模式缺少配置时会报错，不会悄悄回退到演示模式。无需 OpenAI SDK，也未绑定某家供应商。

密钥仅由服务端环境变量读取，不返回到浏览器、不写进数据库。`.env.local` 已加入忽略规则。真实模式会把相关问答发送到配置的模型服务；不要在演示空间加入需要保密的真实资料。

## 数据和写入流程

本地数据库：`data/rag.sqlite`（SQLite WAL）。记录在服务重启后保留。备份前停止服务，复制整个 `data` 目录。可用 `RAG_DB_PATH` 指定其他路径。

1. 先检索记忆并生成回答。
2. 原始问题、回答、最近 6 条对话上下文先独立落库。
3. 一次 LLM 调用提取最多 20 条独立事实（`facts` 数组），每条围绕同一主体的一个可独立更新的属性，各自生成 Embedding。仅提问、寒暄且无新增信息时允许不生成摘要。多条事实共享原始问答，不丢失必要上下文；回答证据按原文 ID 去重。
4. 每条事实寻找热区最多 3 条相似候选，达到 `RAG_MERGE_THRESHOLD`（默认 0.65）后，所有有候选的新事实统一在一次 LLM 调用中批量判断；没有候选时不调用合并模型。原始来源在请求中去重。这个值只决定是否送审，不会按分数自动合并。同一轮拆出的事实不再互相合并，同一旧记忆最多合并一次；候选争用或无效输出时保留独立摘要，不追加模型调用。每次问答最多一次摘要调用、一次合并调用，回答生成和本地 Embedding 另计。
5. 只有同一事实的重复、必要补充或明确更新才合并；仅主题相同不足以合并。更晚的明确长期个人偏好可以更新旧偏好，无需用户提供日历日期；“仅这次”的要求不覆盖长期偏好。合并后两条旧摘要进入冷区，新摘要位于热区，包含扁平化的全部 `sourceIds` 和两个 `parentIds`。冷区仅用于查看合并历史，不参与检索；读取原文直接使用热区记忆的全部 `sourceIds`，无需遍历旧摘要。拆分与关系判断依赖模型，不能保证每次完全遵循语义规则。摘要仅提取本轮用户新增信息，不把助手复述的历史再次当成新事实。

一次写入只进行一批合并：候选来自本轮写入前的热区快照。产生多条新记忆后立即保存，不递归重新检索或合并。未来收到相关新信息时，这些记忆才有机会成为候选；没有后台自动整理任务。
6. 合并使用事务及旧记录状态校验，避免并发整理覆盖已有结果。摘要失败时仍保留原始问答；合并失败时尽量保留独立摘要，并在界面提示。

历史助手回答一律视为未验证，提示词要求保留条件、否定、时间与不确定性。当前版本没有事实验证、用户确认或重试队列；模型整理失败后可能留下未索引原文，界面会提示，需后续增加重建索引功能。

## 两种检索策略

- **条件关联检索**：首轮从热区取相似度达标的最多 20 条候选，在原文预算内选最多 6 条摘要。首轮少于 3 条，或相似度达到 0.75 的结果少于 2 条，并且还有预算时，才展开第二轮。没有首轮证据、预算用尽或首轮达到规则要求时，不扩展。这个规则只是“是否尝试补充”的启发式判断，不等于理解了问题是否已被完整回答。
- **第二轮**：仅在热区中先过滤与原问题不相关的记忆，再按各首轮摘要找最多 5 个邻居。跨分支按记忆 ID 去重，使用 `原问题相似度 × 75% + 邻居相似度 × 25%` 排序，最多补充 6 条摘要，并与首轮共用原文条数、长度预算。仅引用重复原文、没有提供新证据的摘要不会重复选入。低分候选也仅来自热区。
- **摘要 → 原文追溯**：使用同样的首轮阈值、条数和预算规则，直接按来源 ID 读取原始问答，不执行第二轮。

预算根据**去重后、实际发送的原始问答**计算，不是摘要长度。默认最多 12 条原文、单条正文最多 5,000 字符；发送的历史证据 JSON（包含来源编号、ID、时间、转义开销）同时受 18,000 字符和 6,000 **估算** tokens 限制。token 使用 ASCII 约 4 字符/token、非 ASCII 约 1.5 tokens/码点的启发式估算，**不是千问精确 tokenizer**。这些限制只针对历史证据，不包含系统提示词、当前问题和最近对话，因此不是整个请求的 token 上限。

长记录必要时截取、标记 `truncated`，不会覆盖数据库原文；过短的残片不选入。一条摘要来源过多时优先选较新的原文。检索结果的 `context` 即实际发送给模型的历史证据，`records` 保留对应完整原文，`trace` 返回触发原因、候选数量、预算参数和实际用量。页面显示同一份证据及截断状态，不再出现“展示来源与模型实际接收内容不一致”。

重复上下文也会去重传输：合并资料将相同 role/content 的消息放入共享 `contexts` 字典，各原文按 `contextIds` 保留顺序和重复出现的位置；回答证据中的重复消息引用先前完整证据的来源编号和消息位置。被截断的证据不能作为引用目标。数据库原文保持完整，去重不额外调用模型，也不进行语义删减。

记忆整理在原有的一次批量 LLM 调用内输出 `action`：`merge` 合并同一事实的重复或补充，`replace` 以明确更新后的值为当前值，`delete` 撤回目标热区记忆，`add` 保留独立新事实。LLM 只能操作本轮向量筛选出的候选；找不到候选时无法保证完成覆盖或撤回，不会全库搜索删除。旧 relation 输出仍兼容。

删除要求 `relation=retract`，并逐字提供本轮问题中的 `deletionQuote`；代码校验候选归属、引用依据和热区状态，模型仍负责判断语义。删除是退出检索并保留归档，不是彻底清除个人数据，也不清理其他记忆来源或最近对话中的相同信息。合并、覆盖和删除记录到 SQLite `memory_operations`；删除指令保存在冷区供追溯。异常结果保留独立摘要并返回 partial。普通否定或临时要求不应解释为删除。

所有阈值和预算都可在 `.env.local` 中调整：

| 配置 | 默认值 | 用途 |
|---|---|---|
| `RAG_SEARCH_THRESHOLD` | 0.5 | 原问题相关性最低分，演示模式使用 0.08；无达标结果时仅展示最接近的 3 条热区候选，不发送给模型 |
| `RAG_FIRST_CANDIDATES` / `RAG_FIRST_LIMIT` | 20 / 6 | 首轮候选数 / 实际选中摘要上限 |
| `RAG_NEIGHBORS_PER_SEED` / `RAG_SECOND_LIMIT` | 5 / 6 | 每个起点的邻居数 / 第二轮选中摘要上限 |
| `RAG_MAX_RECORDS` | 12 | 两轮共用的原文条数上限 |
| `RAG_CONTEXT_MAX_CHARS` / `RAG_CONTEXT_MAX_TOKENS` | 18000 / 6000 | 历史证据字符 / 估算 token 预算 |
| `RAG_RECORD_MAX_CHARS` | 5000 | 单条原文正文的字符上限 |
| `RAG_MIN_FIRST_RESULTS` | 3 | 首轮低于此数量时尝试扩展 |
| `RAG_MIN_STRONG_RESULTS` / `RAG_STRONG_SCORE` | 2 / 0.75 | 高相关结果的期望数量 / 分数门槛 |

这些是实验起始值，需要结合实际问答校准。旧的 `RAG_MAX_SOURCES` 不再限制合并；累计来源可以继续增加，完整原文归档保留。

### 阶段摘要与归档

未被阶段摘要覆盖的原文超过 `RAG_STAGE_SOURCE_THRESHOLD=10` 条，或这些完整问答（含上下文）序列化总长度超过 `RAG_STAGE_CHAR_THRESHOLD=12000` 字符时，在同一次批量合并调用中额外生成阶段摘要，最多4000字。检索用的单一事实摘要继续单独生成向量。恰好10条不触发条数条件。

阶段摘要保存当前值、关键变化、日期、条件、否定和不确定性，覆盖来源由代码确定。后续合并判断只读取上一版阶段摘要和未覆盖的新原文；再次积累超过阈值后，同样用「上一版阶段摘要＋新增原文」增量压缩，不重新加载全部归档。模型不能补回摘要已丢失的细节；原文核对通过归档入口按需进行。模型未返回所需阶段摘要时保留独立事实，不追加 LLM 调用。

完整来源 ID 仅在数据库中维护；合并请求只携带未覆盖的原文 ID、阶段摘要和来源数量，避免 ID 列表本身持续消耗 token。合并资料按原文 ID 去重，并受 `RAG_MERGE_INPUT_MAX_CHARS=64000` 和 `RAG_MERGE_INPUT_MAX_TOKENS=20000`（估算）限制。该预算只计算序列化合并资料，不包括系统提示和输出。超过预算则保留独立事实并返回 partial，不静默删减新信息、不追加模型调用。单条阶段摘要最多4000字；整体开销仍取决于本轮事实数、候选数和新原文长度，不能理解为固定 token 数。

回答证据默认由最新未压缩原文和阶段摘要组成，共用条数、字符和估算 token 预算；每个阶段摘要算一条证据。原文 ID 仍完整保留，同一份阶段摘要或原文不会重复发送；不同事实可能共享原始问答，其中一条事实的阶段摘要不会抑制另一条事实所需的原文。模型明确得知阶段摘要是有损整理，不是逐字原文。记忆库来源详情及检索路径中可点击「展开归档原文」按需核对；展开只供用户查看，不会自动追加给 LLM。

新建 `stages` 和 `memory_stages` 表兼容既有数据库，旧记忆保持原样，在后续实际合并达到条件时压缩。演示模式不模拟 LLM 阶段压缩。

支持按 `scope` 隔离记忆；演示/真实模式、Embedding 服务地址和模型名称构成向量空间标识，查询只比较同一空间。更换模型不会自动重建旧向量。同名模型若供应商改变维度，需要重新索引或变更标识；维度不一致时不会产生有效相似度。

## 架构

```text
src/app/page.tsx          对话、冷热区、追溯与配置页面
src/app/api/             chat / memories / search / seed
src/lib/rag.ts           问答、摘要和合并编排
src/lib/retrieval.ts     阈值检索、条件扩展、排序与追溯
src/lib/evidence-budget.ts 原文去重、预算计数和节选
src/lib/providers.ts     可兼容的 LLM 与 Embedding HTTP 适配层
src/lib/store.ts         SQLite 持久化和事务
src/lib/similarity.ts    余弦相似度与演示向量
```

SQLite 保存向量 JSON，当前由服务端 TypeScript 线性计算余弦相似度，**不是 SQLite 向量索引**，适合本地小规模实验。后续可替换存储检索层为 PostgreSQL/pgvector，并把 `src/lib` 独立成包。

接口：

- `POST /api/chat`：`{ scope, question, strategy: "expand" | "sources", history: [{role, content}] }`
- `POST /api/search`：`{ scope, query, strategy }`，只检索，不写入、不生成答案。
- `GET /api/memories?scope=default`：读取当前空间的摘要、原文、统计与不含密钥的配置。
- `POST /api/seed`：`{ scope }`，仅演示模式可用。

## 检查

```powershell
npm.cmd test
npm.cmd run build
```

测试覆盖向量比较、合并冷热区迁移、原文来源保存、过期并发合并拒绝、空间/模型隔离、二跳去重及磁盘持久化。另有本地模拟 HTTP 模型测试，验证真实模式调用链和错误恢复；不代表已验证任何实际模型供应商的效果。

运行 `npm.cmd run test:e2e` 会在 3100 端口自动启动独立演示服务，使用 `.next-e2e` 构建目录和 `data/e2e-rag.sqlite` 测试数据库，退出时关闭测试服务。使用本机 Microsoft Edge 检查对话、合并、追溯、预算显示、空间隔离和移动布局，截图写入 `artifacts/`。不改写 `.env.local` 的模型模式，也不使用 3000 端口真实服务的数据。

运行 `npm.cmd run test:live` 会读取 `.env.local`，使用真实 Embedding 和 LLM 接口验证“首轮充分不扩展、仅两条时扩展、超长原文遵守预算、原文引用回答”。测试数据位于内存数据库，不写入用户记忆；会产生模型调用费用，报告写入 `artifacts/retrieval-live-check.json`。

这是本机单用户原型：空间隔离不是权限认证。对外部署前需要身份验证、权限校验、配额限制、任务队列和生产数据库部署；不适合直接公开当前接口。SQLite 需要可写的持久磁盘，不适合直接部署在短生命周期的无服务器文件系统上。
